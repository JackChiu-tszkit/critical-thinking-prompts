# Best Practices

## Match critique depth to risk

Use brief answers for simple factual questions. Use structured critical analysis for expensive, consequential, irreversible, or uncertain decisions.

## Separate evidence from opinion

Ask the assistant to label confirmed facts, assumptions, inferences, and unknowns. A plausible counterargument is not automatically a true one.

## Use falsification criteria

Before acting, ask: "What observable result would show that this plan is wrong?" Set decision thresholds when possible.

## Prefer minimal experiments

For product and architecture decisions, run the cheapest meaningful experiment before building the full solution.

## Avoid adversarial theater

A good reviewer may agree with a sound proposal. The goal is better reasoning, not disagreement quotas.

## Keep review independent

Have a second model or a separate context inspect the actual artifacts, tests, and acceptance criteria. Independent review is useful but does not replace execution or human oversight.

## Protect confidential information

Do not paste credentials, private client data, or proprietary code into tools without appropriate authorization and data-handling review.
