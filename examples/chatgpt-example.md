# Example: ChatGPT challenges an AI startup proposal

## Initial idea

> I want to launch an AI agent business. I will use LangGraph, MCP, FastAPI, and multiple LLMs from day one.

## Better analysis

**Assumptions to test**

- Customers have a recurring, valuable problem that requires an agent rather than automation or a conventional app.
- Multi-step orchestration is needed in the first release.
- MCP interoperability creates immediate customer value.
- Multiple model providers are worth their integration and operational cost.

**Skeptical counterpoint**

A technically sophisticated architecture is not evidence of product-market fit. Building integrations before confirming customer demand may delay the first sale.

**Alternatives**

| Approach | Benefit | Trade-off |
| --- | --- | --- |
| Manual concierge pilot | Validates customer demand quickly | Does not scale |
| Simple Python + one model | Low complexity, fast MVP | Limited orchestration |
| Full agent platform | Extensible for validated complex workflows | Higher cost and maintenance |

**P1 — Next experiment**

Interview five target users about one recurring workflow. Prototype a single end-to-end outcome and measure time saved, error rate, and willingness to pay. The number five is a starting experiment, not a statistically representative sample.

**P2 — Longer-term leverage**

Add orchestration, MCP, and model routing only when observed requirements justify them. Record the evidence that triggers each architectural upgrade.

**What would change the conclusion?**

If real pilot customers need multi-step recovery, several independently maintained tool integrations, or provider redundancy, more advanced architecture becomes defensible.

*Illustrative example, not a report of a real experiment.*
